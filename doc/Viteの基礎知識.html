01 — OVERVIEW

Viteとは何か

Vite（ヴィート）は、ReactやTypeScriptで作るWebアプリの 開発サーバーと本番ビルドを担当するツールです。

DEV

開発中に表示する

ソースファイルをブラウザへ届けます。保存した変更をすぐ画面へ反映できます。

HMR

変更部分だけ更新する

ページ全体を読み直さず、変更したモジュールだけを差し替えます。

DIST

本番用にまとめる

JavaScriptやCSSを最適化し、配布用のdist/を生成します。

Viteはアプリそのものではありません。アプリを作り、確認し、配布できる形へ整える「開発道具」です。

02 — RELATIONSHIP

npm、Node.js、Viteの関係

npm run devと入力しても、実際の開発サーバーを動かすのはViteです。 npmはpackage.jsonの指示を読み、Viteを呼び出します。

あなた コマンドを入力
npm scriptsを探す
package.json 実行内容を定義
Vite サーバーやビルドを実行

Node.js

ブラウザの外でJavaScript製ツールを動かす実行環境です。ViteもNode.js上で動きます。

npm

パッケージの管理と、package.jsonに登録されたコマンドの実行を担当します。

このプロジェクトでは、package.jsonに次のような対応が定義されています。 

"scripts": {
  "dev": "vite",
  "build": "tsc --noEmit && vite build",
  "preview": "vite preview"
}
03 — COMMANDS

最初に覚える3つのコマンド

開発、成果物の生成、成果物の確認という3段階に分けて覚えると迷いません。

1. 開発する

ソースを直接確認
npm run dev

Viteの開発サーバーを起動します。表示された http://localhost:5173/などのURLをブラウザで開きます。

  • ファイル保存後、画面がすばやく更新される
  • 開発者向けのエラーを確認しやすい
  • dist/は更新されない

2. 本番用にまとめる

distを生成
npm run build

このプロジェクトでは、先にTypeScriptの型検査を行い、成功した場合だけ Viteが本番用ファイルを生成します。

  • JavaScriptやCSSを圧縮・最適化する
  • ファイル名へハッシュを付けてキャッシュ対策を行う
  • 完成したファイルをdist/へ出力する

3. ビルド結果を確認する

distを表示
npm run preview

すでに作られているdist/をローカルサーバーで表示します。 本番に近い状態を確認するためのコマンドです。

  • preview自体はビルドを行わない
  • ソース変更後は、先にbuildをやり直す
  • 公開用サーバーとして使うものではない
04 — COMPARISON

dev・build・previewの違い

「何を入力にして、何が更新されるか」に注目すると違いが明確になります。

コマンド 目的 表示するもの distの更新 終了方法
npm run dev 開発と修正 src/などの最新ソース しない Ctrl+C
npm run build 本番成果物の生成 画面は起動しない する 完了すると自動終了
npm run preview 成果物の最終確認 dist/ しない Ctrl+C
05 — BUILD FLOW

Viteがビルドするときの流れ

難しい内部処理をすべて覚える必要はありません。入力から dist/までの大きな流れを押さえましょう。

01
index.htmlを入口として読む

ViteはHTMLから参照されるJavaScriptやCSSをたどります。

02
モジュールのつながりを調べる

importをたどり、必要なファイルの関係を整理します。

03
ブラウザで使える形へ変換する

React、TypeScript、CSSなどを配布可能な形式へ処理します。

04
ファイルを最適化する

不要なコードを省き、圧縮し、キャッシュに適した名前を付けます。

05
dist/へ出力する

サーバーへ配置できるHTML、CSS、JavaScriptが完成します。

開発時のHMR

変更した部分だけをブラウザへ送り直すため、毎回フルビルドする必要がありません。

本番用build

完成時にまとめて最適化します。ソースを変更したら、以前のdistは自動更新されません。

06 — PROJECT FILES

プロジェクト内の主なファイル

Viteを使うときは、「編集する場所」と「生成される場所」を区別することが大切です。 

survey-learning-lab/
├── index.html          # Viteが最初に読むHTML
├── package.json       # npmコマンドと依存パッケージ
├── vite.config.ts     # Viteの設定
├── tsconfig.json      # TypeScriptの設定
├── src/               # 自分が編集するアプリのソース
│   ├── main.tsx
│   ├── App.tsx
│   └── styles.css
├── node_modules/      # npmが管理するパッケージ
└── dist/              # buildで生成される本番成果物

編集する

通常はsrc/、index.html、設定ファイルを編集します。

直接編集しない

dist/とnode_modules/はツールが管理するため、直接直しません。

07 — COMMON MISTAKES

よくある勘違い

  • ×
    devで画面が変わったから、distも新しくなった

    devは最新ソースを表示するだけです。distを更新するにはbuildが必要です。

  • ×
    previewを起動すれば、自動でビルドされる

    previewは既存のdistを表示するだけです。先にbuildを実行します。

  • ×
    表示を直すためにdistのCSSを編集する

    次のbuildで消えます。必ずsrc/styles.cssなどのソースを直します。

  • ×
    開発サーバーを閉じるにはブラウザを閉じればよい

    サーバーはターミナルで動いています。起動したターミナルで Ctrl+Cを押します。

08 — TROUBLESHOOTING

困ったときの見方

Port 5173 is in use と表示された

5173番ポートを別のサーバーが使用しています。Viteが5174番などへ自動変更した場合は、 ターミナルに表示された新しいURLを開きます。不要なサーバーは Ctrl+Cで終了します。

npm run devでコマンドが見つからない

プロジェクトのディレクトリにいるか、package.jsonがあるかを確認します。 依存関係が未導入の場合は、プロジェクトの手順に従って準備します。

previewの画面が古い

ソース変更後にbuildしていない可能性があります。previewを止め、 npm run buildを実行してから、もう一度previewを起動します。

buildが失敗した

エラーの最初の数行と、ファイル名・行番号を確認します。このプロジェクトでは TypeScriptエラーがあるとViteのビルドへ進みません。まず型エラーを直します。

09 — PRACTICE

自分で試す練習手順

「開発表示」と「ビルド結果」の違いを自分で確認すると、3コマンドの役割が定着します。

  1. npm run devを実行し、表示されたURLを開く
  2. ソースの小さな文章を変更し、保存すると画面へ反映されることを確認する
  3. Ctrl+Cで開発サーバーを終了する
  4. npm run buildを実行し、dist/が更新されることを確認する
  5. npm run previewを実行し、ビルド結果をブラウザで確認する
  6. Ctrl+Cでpreviewサーバーを終了する
QUICK REFERENCE

最後に覚える3行

npm run dev # 最新ソースで開発
npm run build # distを更新
npm run preview # distを確認

開発中はdev、更新完了後はbuild、完成したdistの確認はpreviewです。

さらに詳しく確認するときは、 Vite公式日本語ドキュメント を参照してください。
