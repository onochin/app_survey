# 5. 第4章の教育方針

この章の目的は、方式名や精度値を暗記することではありません。

中心となる問いは、

> 同じGNSSなのに、なぜいろいろな測位方式があるのか？

です。

学習者が方式を見るときに、少なくとも次の軸で整理できるようにしてください。

```text
① 基準・補正・補強情報はどこから来るか
② 自分で現場基準局を設置する必要があるか
③ リアルタイムで求めるか、後処理するか
④ 現場条件や目的に合っているか
```

特に、

```text
衛星測位システム ≠ 測位方式
```

を明確にしてください。

GPS / QZSS / Galileo等を利用していることと、RTK / CLAS / スタティック等の測位方式は別の分類です。

また、

> 受信機が1台だから単独測位

とも限らないことを示してください。

ネットワーク型RTKやCLASでは、現場側の受信機が1台でも外部の基準・補強情報を利用します。

# 8. カード1「GNSS測位方式を比較する」

章ヘッダーと導入です。

最初の問い：

> 同じGNSSなのに、なぜいろいろな測位方式がある？

6方式を提示してください。

```text
単独測位
DGNSS
自前基準局RTK
ネットワーク型RTK
CLAS
スタティック
```

一言説明：

```text
単独測位
→ 基準局等からの補正情報を使わず位置を求める

DGNSS
→ 基準側の補正情報を利用する

自前基準局RTK
→ 自分で基準局を設置する

ネットワーク型RTK
→ 配信サービス側の基準情報を利用する

CLAS
→ みちびきから補強情報を受ける

スタティック
→ 一定時間観測して後から解析する
```

ここでは精度の具体値は並べないでください。

重要メッセージ：

> 測位方式が違っても、GNSS衛星そのものが別物になるわけではありません。基準となる情報の得方、解析方法、情報経路、結果を得るタイミングなどが異なります。

# 10. カード3「単独測位からDGNSSへ」

単独測位について、初心者向けの入口は、

> 補正情報を使わず、観測点自身のGNSS観測から位置を求める

としてください。

第2章で扱った、

* 衛星時計
* 衛星軌道
* 電離層
* 対流圏
* マルチパス
* 観測ノイズ

などを新しい誤差項目として増やさず、既習内容として接続してください。

## DGNSS

位置が分かっている基準側のGNSS観測から得られる補正情報を利用し、単独測位に含まれる誤差の影響を小さくする考え方を示してください。

模式図：

```text
             GNSS衛星
           ↓         ↓

      基準局A       P1
   位置を知っている   位置を求めたい
       ↓
   GNSS観測
       ↓
   補正に使う情報
       └────────→ P1
```

「基準局Aの座標差を単純にそのままP1から引く」ような過度な単純化はしないでください。

DGNSSからRTKへの橋渡しとして、

> 基準側の情報を利用して誤差を低減する考え方から、基準局・移動局の搬送波位相等を使う高精度な相対測位へ進む

としてください。

DGNSSを「コードだけ」、RTKを「搬送波だけ」と断定する表現にはしないでください。

カード3は静的な左右比較としてください。

# 11. カード4「自前基準局RTKとは？」

第4章の重要カードです。

中心となる流れ：

```text
基準局AのGNSS観測
        ＋
移動局P1のGNSS観測
        ↓
相対的なRTK解析
        ↓
A → P1 の相対的な位置関係
        ↓
基準局Aの既知座標と結び付ける
        ↓
P1の成果座標
```

## 11.1 基線

ここで「基線」を入口として紹介してください。

> 基線：基準局Aから移動局P1までの相対的な位置関係を表すもの。

第7章で詳しく扱うため、具体的な基線解析や二重差等へ進まないでください。

## 11.2 基準局座標が成果の土台になる

次の教材用模式値を使用してください。

正しい場合：

```text
基準局A.X = 1000.000 m
A → P1 のX方向成分 = +12.345 m

P1.X = 1012.345 m
```

基準局座標を誤入力した場合：

```text
基準局A.X = 1000.500 m
A → P1 のX方向成分 = +12.345 m

P1.X = 1012.845 m
```

重要メッセージ：

> 相対的な位置関係を高精度に求めても、出発点となる基準局座標が誤っていれば、P1の成果座標もその影響を受ける。

> FIXは、基準局へ入力した座標の正しさまで保証するものではない。

## 11.3 ここは操作を入れる

カード4では、

```text
正しい基準局座標
基準局Xを +0.500 m 誤入力
```

の2状態を切り替えられるようにしてください。

切替時に、

* 基準局X
* A→P1の相対成分
* P1.X
* FIX状態

が明確に比較できること。

両方とも教材上はFIXとし、

> FIXなのに成果が0.500 mずれる

因果関係を視覚化してください。

複雑な自由入力やスライダーは不要です。

* 基線解析 / FLOAT / FIX → 第7章

へ送ってください。

# 12. カード5「ネットワーク型RTKとは？」

中心となる問い：

> 自分で基準局を置かないのに、なぜRTKができる？

自前RTKとネットワーク型RTKを左右に常時表示してください。

## 自前RTK

```text
自分の現場基準局
      ↓
    移動局
```

## ネットワーク型RTK

```text
電子基準点網など
      ↓
配信側の処理
      ↓
インターネット
      ↓
   移動局P1
```

重要メッセージ：

> ネットワーク型RTKは「基準となるGNSS観測を利用しない」という意味ではありません。

> 利用者自身が現場基準局を設置する代わりに、電子基準点網などを利用した配信側の仕組みを使います。

比較項目：

```text
現場基準局
情報の送り元
主な通信経路
移動局
リアルタイム
成果確認
```

「ネットワーク型RTKならFIXだけ確認すればよい」という表現は禁止です。

座標系、高さ、アンテナ高、既知点確認・再観測、上空視界等の品質確認は引き続き必要であることを示してください。

カード5には切替操作を追加せず、左右比較＋比較表としてください。

# 13. カード6「CLASとは？」

最重要メッセージ：

> CLASは「ネットワーク型RTKのインターネットなし版」ではありません。

ネットワーク型RTKとCLASの情報経路を左右比較してください。

## ネットワーク型RTK

```text
電子基準点網など
      ↓
配信サービス
      ↓
インターネット
      ↓
     P1
```

## CLAS

```text
電子基準点等を利用
      ↓
CLAS補強情報を生成
      ↓
   みちびき
      ↓
     L6D
      ↓
CLAS対応受信機 P1
```

## 第2章との接続

```text
L1 / L2 / L5等
→ GNSS測位に利用する信号

L6D
→ CLASの補強情報を届ける
```

重要：

> L6DでP1までの距離を測っている、という意味ではない。

> みちびきからCLAS補強情報を受信することと、みちびきだけを使って測位することは別である。

携帯インターネット通信を必要とせず補強情報を受信できるため、通信圏外では検討候補になり得ることを示してください。

ただし、

> 携帯圏外ならCLASなら必ず測れる

という表現は禁止です。

上空視界、衛星遮蔽、マルチパス、対応機器、必要精度等を確認する必要があります。

CLAS内部処理やPPP-RTKの詳解は第10章へ送ってください。

カード6には切替操作を追加しないでください。

# 16. カード9「現場条件から測位方式を選ぶ」

このカードは第4章で最も操作を重視するカードです。

目的：

> 条件を変えると、検討候補となる測位方式が本当に変化することを体験する。

## 16.1 条件

最低限、次を扱ってください。

```text
必要な位置精度
- 概略
- 高精度

結果が必要な時期
- 現場ですぐ
- 後処理でもよい

携帯通信
- 良好
- 不安定・圏外

現場基準局
- 設置できる
- 設置しない・できない

既知点
- 利用できる
- 現場付近にはない

上空視界
- 良好
- 厳しい
```

自由度を増やしすぎないでください。

## 16.2 「正解」やランキングではなく「検討候補」

画面には、

```text
今回の条件から検討候補
```

として方式と理由を表示してください。

「◎1位」「△3位」のような固定ランキングは不要です。

条件だけでは一意に決められない場合は、複数候補を表示してください。

不十分な条件で強引に1方式へ決定しないでください。

## 16.3 プリセット現場

最低限、次の5ケースを用意してください。

### ケースA：一般現場・通信良好

```text
目的：高精度なP1を現場ですぐ取得
携帯通信：良好
現場基準局：設置しない
上空視界：良好
```

主な検討候補：

```text
ネットワーク型RTK
```

理由：

* 現場基準局を自分で設置しなくてよい
* インターネット経由で必要な情報を受けられる
* リアルタイム測位に向く

### ケースB：山間部・携帯圏外

```text
目的：高精度なP1を現場ですぐ取得
携帯通信：不安定・圏外
現場基準局：設置しない
上空視界：比較的良好
```

主な検討候補：

```text
CLAS
```

理由：

* 携帯インターネットに依存しない
* 現場基準局を自分で設置しない
* 対応受信機、上空視界、必要精度等の確認が必要

### ケースC：既知点あり・自前基準局を設置できる

```text
目的：複数の調査点を高精度でリアルタイム測位
携帯通信：不安定
既知点：利用できる
現場基準局：設置できる
```

主な検討候補：

```text
自前基準局RTK
```

理由：

* 既知点へ基準局を設置できる
* 基準局・移動局を自分で管理できる
* 通信構成によっては携帯インターネットに依存しない運用も検討できる

### ケースD：高精度な基準点を作る

```text
目的：今後の測量の基準となる高精度な点
結果：現場ですぐ必要ではない
一定時間の同時観測：可能
```

主な検討候補：

```text
スタティック
```

理由：

* 複数地点で同時観測できる
* 観測データを蓄積できる
* 後処理による基線解析ができる

### ケースE：概略位置だけ必要

```text
必要精度：概略
補正・補強情報：利用しない
```

主な検討候補：

```text
単独測位
```

「高精度な方式ほど常に良い」という印象を与えないでください。

## 16.4 条件変更で候補理由を変化させる

例：

```text
携帯通信：良好
現場基準局：設置しない
結果：リアルタイム
```

ではネットワーク型RTKを候補とし、

```text

```

へ変更した場合は、

のように、理由も含めて変化させてください。

## 16.5 上空視界が厳しい場合

> GNSS方式を選ぶ前に、GNSS観測条件そのものを確認してください。

# 21. 確認問題1

テーマ：

```text
単独測位とDGNSS
```

問題：

> 単独測位とDGNSSの違いとして、最も適切なのはどれか。

A.

> 単独測位は基準局等からの補正情報を使わず、DGNSSは基準側の観測から得た補正情報を利用する。

B.

> 単独測位は搬送波位相だけを使い、DGNSSはコードだけを使う。

C.

> DGNSSでは必ず自分で現場基準局を設置する。

D.

> 単独測位ではGNSS衛星を1機しか利用できない。

正解：

```text
A
```

正答理由：

> 単独測位では観測点自身が受信したGNSS信号を中心に位置を求める。DGNSSでは位置が分かっている基準側の観測から得た補正情報を利用して、単独測位に含まれる誤差の影響を小さくする。

誤答理由：

B：

> 単独測位とDGNSSの違いを「コードか搬送波か」だけで分けるものではない。

C：

> DGNSSにはさまざまな提供形態があり、必ず利用者自身が現場基準局を設置するとは限らない。

D：

> 単独測位でも複数衛星を利用して位置を求める。

# 22. 確認問題2

テーマ：

```text
自前基準局RTK
```

問題：

> 自前基準局RTKで、基準局AからP1までの相対的な位置関係を高精度に求めることができた。しかし、基準局Aへ入力したX座標が実際より0.500 m大きかった。最も適切な説明はどれか。

A.

> FIXしていれば0.500 mの誤りは自動的に取り除かれる。

B.

> 基準局座標は基線解析には使われないのでP1には影響しない。

C.

> P1の成果座標も誤った基準局座標の影響を受ける。

D.

> 基準局座標が誤っている場合は必ずSINGLEになる。

正解：

```text
C
```

正答理由：

> RTKで基準局と移動局の相対的な位置関係を高精度に求めても、その結果を基準局の既知座標へ結び付けてP1の成果座標を求める。そのため基準局座標が0.500 mずれていれば、P1の成果もその影響を受ける。

誤答理由：

A：

> FIXは入力した基準局座標そのものの正しさを保証しない。

B：

> 基準局座標はP1の最終成果を位置基準へ結び付けるうえで重要である。

D：

> 誤った基準局座標を設定していてもFIXする場合がある。
