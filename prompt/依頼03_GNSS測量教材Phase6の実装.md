# 5. 第6章の教材メタデータ

教材名：

```text
GNSS測量
```

章番号：

```text
6
```

章タイトル：

```text
自前RTK② 補正情報を届ける
```

安定した章ID：

```text
gnss-correction-delivery
```

到達目標：

> 自前RTKで、基準局側の情報がRTCMとしてどのように表され、Ntripやその他の通信経路を通って移動局へ届くかを説明し、RTCM・Ntrip・Caster・Mountpointの役割を区別できる。また、RTCMが正常に届かない場合に、情報経路を順番に確認できる。

章終了時に最低限、次を説明できることを目標としてください。

* 基準局はP1の完成座標を送っているわけではない
* 基準局位置やGNSS観測等がRTCMとして表現される
* RTCMとNtripは別物
* RTCMは複数種類のメッセージが継続して流れるストリーム
* Ntrip Server / Caster / Clientの役割を区別できる
* MountpointはRTCM番号ではなくストリーム識別名
* Ntripは公衆インターネット必須とは限らない
* Ntrip以外の経路でもRTCMを届ける構成がある
* 接続中とRTCMが継続更新されていることは別
* RTCMが届いても、それだけでFIX成立を意味しない
* RTCMが届かない場合に上流から順に切り分けられる

# 12. カード2「基準局は何を移動局へ送る？」

最重要の誤解防止：

> **基準局がP1の完成したX・Y・高さを計算して移動局へ送っているわけではない。**

基準局側から送る情報を、大きく次の2種類で示してください。

```text
① 基準局はどこにいる？

② 基準局では衛星をどう観測した？
→ 基準局側のGNSS観測情報
```

必要に応じて「その他の補助情報」も小さく示して構いません。

模式図：

```text
          GNSS衛星
       ↙            ↘
【基準局A】        【移動局P1】

                        ↓
                  第7章で扱う
```

RTCM例：

```text

→ GPSの観測情報

1097

```

RTCM 1005を、

```text
平面直角座標X・Yそのもの
```

とは説明しないでください。

> 基準局・基準局ARPの位置を表す情報

# 13. カード3「RTCMとは？」

中心メッセージ：

> **RTCMは、基準局の位置やGNSS観測などを、機器どうしで共通して扱えるように決めたデータ形式・メッセージ規格。**

初心者向けには、

```text
RTCM
＝ GNSS情報の共通の書き方
```

という補助表現を使用して構いません。

RTCMを、

* 1個の補正値
* P1の完成座標
* Ntripそのもの
* Casterそのもの

として説明しないでください。

## 13.1 ストリームとして流れる

次のような模式図を表示してください。

```text
基準局A
  ↓

RTCM 1005
基準局ARP位置

RTCM 1077
GPS観測

RTCM 1097
Galileo観測

RTCM 1127
BeiDou観測

RTCM 1077
次の時刻のGPS観測

RTCM 1097
次の時刻のGalileo観測

...
```

重要：

> RTCMは「1回送って終了する1個の完成ファイル」という理解にしない。

複数のRTCMメッセージがストリームとして継続的に流れることを図示してください。

各RTCMメッセージがすべて同じ周期で送信されるような表現は避けてください。

## 13.2 移動局側

利用者が、

```text
1005
1077
1097
1127
```

を1個ずつ選んで組み合わせるわけではありません。

> 受信機が、届いた適切なRTCMと移動局自身のGNSS観測を内部で整理・利用し、測位解を継続的に更新する。

としてください。

FLOAT / FIXの解析詳細には進まないでください。

# 15. カード5「Casterは何をしている？／Mountpoint」

## 15.1 Caster

中心メッセージ：

```text
Caster
＝ 複数のGNSSデータストリームを扱う配信所
```

基本役割：

* Ntrip Server等からストリームを受け取る
* ストリームを識別する
* Ntrip Clientへ配信する

Casterを、

```text
P1のRTK解析を行う装置
FLOAT → FIXを計算する装置
```

とは説明しないでください。

## 15.2 Mountpoint

中心メッセージ：

```text
Mountpoint
＝ Caster内の1本のGNSSデータストリームを識別する名前
```

教材例：

```text
Ntrip Caster

Mountpoint：BASE_A
├─ 1005
├─ 1077
├─ 1087
├─ 1097
├─ 1127
└─ ...継続して流れる

Mountpoint：BASE_B
└─ 基準局BのRTCMストリーム

Mountpoint：BASE_C
└─ 基準局CのRTCMストリーム
```

重要：

> MountpointはRTCMメッセージ1個ごとの名前ではありません。

```text
1005 = Mountpoint
1077 = Mountpoint
```

とはしないでください。

また、

> Mountpointは物理的なアンテナ据付点を意味する言葉ではない。

ことも小さく補足してください。

教材上は、

```text
BASE_A
→ 基準局AのRTCMストリーム
```

という分かりやすい1対1の例を使用して構いません。

ただし小さく、

> 実際の構成では、同じ基準局から設定の異なる複数ストリームを別Mountpointとして提供する場合もある。

程度を補足して構いません。

## 15.3 Host / Port / Mountpoint

設定項目の意味を短く整理してください。

教材用例：

```text
Host       ntrip.example.jp
Port       2101
Mountpoint BASE_A
```

これは**実在サービスではない教材用仮想値**と明示してください。

意味：

```text
Host
→ どのCasterへ接続するか

Port
→ どの通信口を使用するか

Mountpoint
→ どのGNSSデータストリームを受信するか
```

カード5は静的としてください。

# 17. カード7「RTCMの届け方はNtripだけ？」

中心となる問い：

> **携帯通信圏外では、自前RTKはできないのでしょうか？**

答え：

> **Ntrip以外の方法でRTCMを移動局へ届ける構成もあります。**

最重要整理：

```text
RTCM
＝ 中身

Ntrip
＝ 届け方の1つ
```

## 17.1 左右比較

### Ntripを使用

```text
基準局
 ↓
RTCM
 ↓
Ntrip Server
 ↓
IPネットワーク
 ↓
Caster
 ↓
Mountpoint
 ↓
Ntrip Client
 ↓
移動局
```

### Ntripを使用しない直接伝送

```text
基準局
 ↓
RTCM
 ↓
無線・シリアル等
 ↓
移動局
```

重要：

> Ntripを使わない場合でもRTCMそのものがなくなるわけではない。

また、

```text
Ntripを使わない直接伝送
→ Caster不要
→ Mountpoint不要
→ Ntrip Server / Client不要
```

と整理してください。

## 17.2 「直接RTCM」という表現

「直接RTCM」は正式な通信規格名として使用しないでください。

必要な場合は、

> 本教材では、Ntrip / Casterを介さず別の通信経路でRTCMを直接移動局へ届ける構成を、説明上「RTCMを直接届ける」と表現する。

としてください。

## 17.3 携帯圏外

中心メッセージ：


# 24. 問1「RTCMは何をしている？」

