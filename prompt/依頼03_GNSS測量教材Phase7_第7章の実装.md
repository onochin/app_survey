# 5. 第7章の教材メタデータ

教材名：

```text
GNSS測量
```

章番号：

```text
7
```

章タイトル：

```text
自前RTK③ 基線解析とFIX
```

安定した章ID：

```text
gnss-baseline-fix
```

到達目標：

> 基準局Aと移動局P1のGNSS観測を比較することで、なぜ共通する誤差の影響を相殺・低減しながら3次元の相対位置「基線」を求められるのかを理解し、搬送波位相の整数アンビギュイティがFLOATからFIXへ進む意味を説明できる。

章終了時に、利用者が最低限次を説明できることを目標としてください。

- RTCMが届いていることとFIX成立は同じではない
- RTKでは基準局と移動局の観測を比較する
- 同じ衛星を2地点で観測して差を見る意味
- 2受信機・2衛星の観測差を組み合わせる二重差の基本イメージ
- 二重差で時計等の共通項を相殺できるが、すべての誤差が消えるわけではない
- 整数アンビギュイティは二重差後も未知量として残る
- FLOATでも位置・基線は推定されている
- FIXはFLOAT値の単純な四捨五入ではない
- 整数候補は複数の観測との整合性から評価される
- FIXでは必要な整数アンビギュイティを固定解として採用する
- 基線は単なる距離ではなく3次元の相対位置関係である
- FIX後も観測・監視は継続し、FLOATへ戻る場合がある
- FIXは成果条件全体の正しさを保証しない
- ミスFIXが起こり得るため、FIX表示と成果採用は別の工程である

# 12. カード2「なぜ基準局AとP1の2地点を比較する？」

最初は、1衛星・2受信機で考えてください。

模式図：

```text
             衛星 G1
            ↙      ↘
       基準局A     移動局P1
        観測A       観測P1
            \      /
             比較
```

中心メッセージ：

> 同じ衛星を基準局Aと移動局P1で対応する時刻に観測し、観測値そのものではなく「2地点の違い」に注目することで、両地点へ共通・類似して入る影響の一部を相殺・低減できる。

## 12.1 誤差の扱い

「すべての誤差が消える」と説明しないでください。

初心者向けには、最低限次の3分類を表示してください。

```text
相殺できる代表例
→ 衛星時計に関する共通項など

近距離なら差が小さくなりやすいもの
→ 大気遅延・軌道誤差等の空間的に相関する影響

残るもの
→ マルチパス
→ 観測ノイズ
→ 地点固有の影響
```

大気・軌道等を「完全に消える」としないでください。

## 12.2 なぜ対応する時刻で観測するか

衛星位置、衛星時計、大気状態等は時間とともに変化するため、基準局と移動局の観測を比較するには、同じ衛星の対応する観測時刻を使うことが重要である、と初心者向けに説明してください。

「同時観測」という言葉は使用して構いませんが、完全に同一瞬間でなければ解析不能という過度な表現にはしないでください。

カード2は静的としてください。

# 13. カード3「なぜ、もう1機の衛星とも比べる？」

カード2の1衛星・2受信機から、2衛星・2受信機へ進めます。

模式フロー：

```text
G1について
P1の観測 − Aの観測
        ↓
差①

G2について
P1の観測 − Aの観測
        ↓
差②

差① − 差②
        ↓
二重差
```

「二重差」という用語は、まず上記の2段階の差を見せた後で名称として提示してください。

## 13.1 時計項の直感的説明

古典的な単一基準局RTKを理解する代表的な説明として、

```text
同じ衛星を2受信機で差を取る
→ 衛星時計に関する共通項を相殺
→ 受信機時計差は残る

別衛星についても同じ差を取る
→ 2つの受信機間差をさらに差し引く
→ 受信機時計差も相殺
```

という順で説明してください。

数式暗記教材にはしないでください。

## 13.2 二重差でも残るもの

次を明示してください。

```text
二重差で代表的に相殺
→ 衛星時計・受信機時計の共通項

近距離で低減しやすい
→ 大気・軌道等の相関する影響

残る
→ マルチパス
→ 観測ノイズ
→ 地点固有の影響
→ 整数アンビギュイティ
```

特に、

> **二重差を取れば整数アンビギュイティが消える**

とは説明しないでください。

整数アンビギュイティは、二重差後も整数として扱うべき未知量として残り、ここからFLOAT / FIXへつながります。

## 13.3 実装上の重要な注意

教材では二重差を、

> **単一基準局RTKの原理を理解する代表的な方法**

として扱ってください。

「すべてのRTK受信機・RTKエンジンが、必ず画面どおりの二重差式を内部でそのまま計算している」と断定しないでください。

非差分・別形式でアンビギュイティを固定する高度な解析方式も存在するためです。

この高度な方式は詳解不要です。

カード3は静的としてください。

Drogger公式資料に二重差原理の適切な直接解説がない場合、無理に「Drogger実機で確認」リンクを付けないでください。

## 15.2 操作

```text
次の観測を見る
```

または同等の分かりやすい操作で、判断材料が増える様子を段階的に見られるようにしてください。

初期状態例：

```text
候補A　整合性：高
候補B　整合性：高
候補C　整合性：中

→ まだ候補を十分に区別できない
→ FLOAT
```

次段階：

```text
候補A　整合性：中
候補B　整合性：高
候補C　整合性：低

→ Bが有力
→ まだ全体の整合を確認
```

最終段階：

```text
追加の観測でも候補Bが整合
        ↓
必要な整数候補を固定解として採用
        ↓
FIX
```

色だけで高・中・低を区別せず、必ず文字・記号を併用してください。

## 15.3 「最良候補」と「固定してよい候補」は別

次を理解できる表示にしてください。

```text
一番良い候補がある
≠
その候補を固定してよいと十分に判断できた
```

他候補との差が十分でない模式ケースではFLOATを維持してください。

特定のratio値、残差閾値、LAMBDAアルゴリズムの内部計算、固定しきい値等は実装しないでください。

## 15.4 複数エポック必須と誤解させない

「次の観測を見る」という教材操作を使用しても、

> **実際のRTKでは、複数衛星・複数周波数・継続して更新される観測等を利用する。条件によっては単一エポックで整数固定が成立する解析もあり、複数時刻の観測が必ず必要という意味ではない。**

という補足を入れてください。

カード5の状態はReact状態だけで管理してください。

# 17. カード7「一度FIXしたら、そのままずっとFIX？」

問い：

> **整数アンビギュイティを一度FIXできたら、その整数は観測終了までずっと使い続けられるのでしょうか？**

中心フロー：

```text

整数を固定
      ↓
その後もGNSS観測を継続
      ↓
新しい観測と整合するか監視
      ↓
整合する
→ FIX維持

整合を維持できない
→ FLOAT等へ戻り再評価
```

## 17.1 FIX = 解析終了ではない

必ず、

```text
FIX
≠ 観測終了
```

と理解できるようにしてください。

## 17.2 サイクルスリップ

ここで初めて、専門用語として小さく紹介してください。

> **サイクルスリップ：搬送波位相を連続追跡している途中で、受信機のロック喪失等により整数波長単位の不連続が生じること。**

模式図：

```text
連続追跡
10 → 11 → 12 → 13 → 14

追跡中断の模式例
10 → 11 → 12 → ? → 17
                 ↑
           位相の連続性が切れた
```

これは波数そのものを実際の距離として数えている図ではなく、連続性の理解用模式図であるとしてください。

## 17.3 誤解防止

次を明示してください。

> FIXからFLOATへ戻るのは、整数アンビギュイティが時間とともに小数へ変化したからではない。

> これまでの固定条件を新しい観測に対して信頼して使い続けられなくなったため、再び推定・評価が必要になる場合がある。

また、

```text
FLOATへ戻った
≠ 必ず受信機故障
```

としてください。

衛星遮蔽、信号追跡中断、基準局側情報の途切れ等を代表例として軽く触れて構いません。

ただし、具体的な現場再測判断は第8章へ送ってください。

カード7は静的としてください。

# 25. 確認問題 Q1「RTCM受信とFLOAT」

問題ID例：

```text
rtcm-received-still-float
```

問題：

> Drogger-GPSで通信状況は正常で、RTCMも継続して受信しています。しかしFixModeはFloatです。最も適切な説明はどれですか？

選択肢：

```text
A
RTCMを受信していれば、本来必ず直ちにFIXする

B
通信は正常でも、整数アンビギュイティをまだ固定できていない場合がある

C
Floatなら基準局のRTCMは一切届いていない

D
Floatは基準局座標が必ず間違っていることを示す
```

正答：

```text
B
```

正答理由：

> RTCM受信とFIX成立は別です。RTCMが届いた後、基準局側情報と移動局自身のGNSS観測を使って整数アンビギュイティを評価します。通信経路が正常でもFLOATのままの場合があります。

誤答理由：

A：

> RTCM受信正常だけでは、整数アンビギュイティの固定を保証しません。

C：

> RTCMを正常受信していてもFLOATはあり得ます。

D：

> 基準局座標の誤りだけがFLOATの原因ではありません。また基準局座標が誤っていてもFIXする場合があります。
