# 2. GNSS教材の基本方針

GNSS教材は、用語暗記ではなく、

```text
図を見る
  ↓
操作する
  ↓
数値・状態の変化を見る
  ↓
仕組みを理解する
  ↓
現場・成果とのつながりを確認する
  ↓
問題を解く
```

という流れを重視する。

シミュレーションや切替操作は、

> 操作によって理解が明確に深まる場面

に絞って使用する。

切り替えても表示や意味がほとんど変わらない場合は、無理に操作を設けず、

- 静的な比較
- 図解
- 表
- フロー

を優先する。

## 4.2 第3章「GNSSの座標と高さ」

第3章では、元期・今期について**概念導入に留める**。

理解させる内容：

- 測量成果には基準となる時点「元期」がある
- 実際に観測する時点を「今期」と考える
- 日本列島は地殻変動で移動している
- 同じ測地系でも、時点が違えば座標値が異なる場合がある
- 「測地系が違うこと」と「座標の時点が違うこと」は別の問題
- 元期・今期をそろえるためにセミ・ダイナミック補正という仕組みがある
- 詳細な処理の流れは後続章で扱う

### 第3章で特に防ぎたい誤解

```text
JGD2011 ＝ 元期
JGD2024 ＝ 今期
```

という理解にしない。

JGD2011 / JGD2024は測地系・測地成果の名称に関する話であり、

```text
元期 / 今期
```

は座標の時点に関する話として区別する。

また、

> 座標値が違う ＝ 測地系が違う

とも限らないことを明確にする。

## 4.3 第3章カード6のUI改善候補

現在のカード6では、

- 元期
- 今期
- 地殻変動による差
- 「元期へそろえる」操作

を扱っている。

ただし、

> 「元期へそろえる」を選んでも、図上の位置は変わるのに右側の仮想値が変化しない

場合、何が補正されたのか理解しにくい。

将来の修正では、次の3つを明確に分けて表示する。

### 元データ

```text
元期成果
X = 1000.000 m
Y = 1000.000 m

今期観測
X = 1000.035 m
Y =  999.982 m

元期 → 今期の変化量
ΔX = +0.035 m
ΔY = -0.018 m
```

### 時点未整合

```text
今回使用している座標

X = 1000.035 m
Y =  999.982 m

今期の座標のまま
```

### 元期へそろえた後

```text
今回使用する成果座標

X = 1000.000 m
Y = 1000.000 m

元期へ補正済み
```

### 符号について

元期から今期への移動量：

```text
ΔX = +0.035 m
ΔY = -0.018 m
```

今期から元期へ戻す補正量：

```text
X：-0.035 m
Y：+0.018 m
```

「移動量」と「戻すための補正量」は符号が逆になることを明示する。

# 5. 第9章「観測データと後処理解析」で本格的に扱う内容

第9章では、元期・今期・セミ・ダイナミック補正を**仕組みとして理解できる教材**にする。

単なる説明ではなく、

> なぜ元期から今期へ行き、最後に今期から元期へ戻るのか

を一連の処理として理解させる。

## 5.1 中心となるフロー

```text
既知点の公表成果
【元期】
      ↓
セミ・ダイナミック補正
元期 → 今期
      ↓
既知点
【今期】
      ↓
GNSS観測・解析
      ↓
新点
【今期】
      ↓
セミ・ダイナミック補正
今期 → 元期
      ↓
新点の成果
【元期】
```

## 5.2 理解させるポイント

### 既知点

既知点の公表成果は、基準となる時点「元期」の座標として扱われる。

### 観測時

GNSS観測は現在の地殻変動後の位置関係を捉えるため、観測時点は「今期」として考える。

### 観測前の補正

対象となる基準点測量では、既知点成果を、

```text
元期 → 今期
```

へ補正し、観測時点へそろえる。

### GNSS観測・解析

既知点と新点を同じ「今期」にそろえた状態でGNSS観測・解析を行い、新点の今期座標を求める。

### 成果化

最終的な新点成果を既存の測量成果と整合させるため、

```text
今期 → 元期
```

へ補正する。

# 6. 第9章で実装したいシミュレーション

第9章では、操作によって理解が明確に深まるため、元期・今期の切替と補正をシミュレーション候補とする。

## 6.1 仮想既知点A

```text
既知点A 公表成果【元期】

X = 1000.000 m
Y = 1000.000 m
```

地殻変動後：

```text
既知点A【今期】

X = 1000.035 m
Y =  999.982 m
```

## 6.2 比較1：時点をそろえない

```text
既知点成果：元期
GNSS観測：今期

→ 時点がそろっていない
```

## 6.3 比較2：既知点を今期へ補正

```text
既知点A
元期
  ↓
セミ・ダイナミック補正
  ↓
今期

→ 観測時点がそろった
```

## 6.4 新点P1

GNSS観測・解析によって、

```text
P1【今期】
X = xxxx.xxx m
Y = xxxx.xxx m
```

を求める。

その後、

```text
P1【今期】
  ↓
セミ・ダイナミック補正
  ↓
P1【元期】
  ↓
成果
```

とする。

### 教材上の中心メッセージ

> 現在の位置を無理に昔の場所へ戻しているのではない。

> 現地は実際に地殻変動で移動しているが、既存の国家座標・基準点成果と整合する共通の基準時点へ成果をそろえている。

# 7. 「測地系」と「座標の時点」を分離して理解させる

第9章では次の比較を明確にする。

| 状態 | 測地系 | 時点 |
|---|---|---|
| 既知点の公表成果 | JGD2024 | 元期 |
| GNSSで観測・解析する位置 | JGD2024 | 今期 |
| 最終成果 | JGD2024 | 元期 |

この比較によって、

> 全部JGD2024でも、時点が違えば座標値が違う

ことを理解させる。

## 7.1 時点補正

```text
JGD2024 / 今期
      ↓
セミ・ダイナミック補正
      ↓
JGD2024 / 元期
```

これは、

> 測地系そのものを別の測地系へ変換すること

とは区別する。

## 7.2 測地基準・CRSの違い

例えば、

```text
別の測地基準
      ↓
座標変換
      ↓
JGD2024
```

のような変換と、元期・今期の時点補正を混同させない。

# 9. 適用範囲についての注意

セミ・ダイナミック補正は重要だが、

> すべてのGNSS利用で必ず行う

とは説明しない。

適用の有無は、

- 測量の種類
- 基準点の使い方
- 必要精度
- 作業規程
- 成果の目的

などによって異なる。

教材では、

> GNSSだから必ずセミ・ダイナミック補正

という暗記にしない。

実務への接続時には、対象業務の作業規程・国土地理院の最新資料を確認する。

# 13. 横断ガイド「GNSS表示・状態の読み方」（案）

GNSS教材には、通常の章とは別に、

> 実機で表示されるGNSSの状態・略語を、迷ったときにすぐ確認できる横断ガイド

を設ける案とする。

これは第5章、第6章……のような順番学習を目的とした章ではなく、

> 実機を使用中に「この表示は何を意味するのか？」と迷ったときに戻る補助教材

として位置付ける。

GNSSトップ等から常時参照できる構成を候補とする。

## 13.1 最初に載せたい早見表

Drogger等の実機表示について、まず次のように短く整理する。

```text
3D DGNSS
→ 補正・補強情報を利用している

3D DGNSS FLOAT
→ RTK解析まで進んだが、
   整数アンビギュイティは未確定

3D DGNSS FIXED
→ RTKの整数アンビギュイティを固定できた
```

教材では、

> DGNSS

と、

> FLOAT / FIXED

が同じ意味の状態表示ではないことを分けて理解させる。

概念上は、

```text
DGNSS
→ 差分補正・補強情報を利用している側の状態

FLOAT / FIXED
→ RTKの搬送波位相解析で、
   整数アンビギュイティが確定しているかどうか
```

として整理する。

## 13.2 実機表示で特に混同しやすい内容

最低限、次を候補とする。

### DGNSS表示とDGNSS測位方式

```text
Drogger画面に DGNSS と表示
≠
必ず「教材で説明するDGNSS方式だけ」を行っている
```

DGNSSという語が、

- 教材上の測位方式名
- 実機上の差分補正・補強状態を示す表示

の両方で使われるため、1対1に対応すると考えない。

### FLOATとDGNSS

```text
3D DGNSS
→ 補正・補強情報を利用している

3D DGNSS FLOAT
→ さらにRTKの搬送波位相解析まで進んでいるが、
   整数アンビギュイティは未確定
```

FLOATは、通常は単なるDGNSS状態より高精度な位置へ進んでいることが期待されるが、

> FLOATなら必ず十分な精度がある

とは説明しない。

### FIXED

```text
3D DGNSS FIXED
→ RTKの整数アンビギュイティを固定解として採用できた状態
```

ただし、

```text
FIXED
≠
成果座標が必ず正しい
```

ことを繰り返し確認する。

基準局座標、アンテナ高、座標系、高さ基準、マルチパス、上空視界等は別途確認が必要。

### 「3D fix」とRTK FIX

一般機器やスマートフォン等で使われる、

```text
3D fix
GNSS fix
```

は、

> 3次元の位置解が得られている

という意味で使われる場合がある。

これは、

```text
RTK FIX
＝ 整数アンビギュイティを固定した固定解
```

とは区別する。

## 13.3 あわせて整理したい迷いやすい用語

横断ガイドには、今後次のような組合せも追加候補とする。

```text
2周波
≠ RTK

マルチGNSS
≠ 複数周波数

L6D
≠ P1までの距離を測る測距信号

CLAS
≠ ネットワーク型RTKのインターネットなし版

基準局が必要
≠ 利用者自身が現場に基準局を設置する

DGNSSの「基準局」
≠ 必ず自前基準局
```

今後、実機確認中に、

> 「この表示は何を意味する？」
> 「教材の用語と実機表示は同じ意味？」

という疑問が出た場合は、この横断ガイドへ追記する。

## 13.4 実機で比較する「2周波」の例

「2周波」といっても、すべてのGNSS受信機が同じ周波数の組合せを使うわけではない。

利用者が実際に使用・所有している機器を例にすると、次のように整理できる。

| 機器 | 2周波の例 | 教材上の位置付け |
|---|---|---|
| 使用中のDrogger | L1 + L2 | 測量用GNSS受信機の具体例 |
| Garmin Forerunner 265 | L1 + L5 | GNSSウォッチでも2周波を利用する具体例 |
| iPhone 15 Pro | L1 + L5系の高精度2周波GNSS | スマートフォンでも高精度2周波GNSSを利用する具体例 |

### 教材上の中心メッセージ

```text
Drogger
L1 + L2
   ↓
2周波

Garmin
L1 + L5
   ↓
2周波

iPhone
高精度2周波GNSS
（L1 + L5系として理解）
   ↓
2周波
```

つまり、

> **2周波＝L1 + L2だけではない。L1 + L5も2周波である。**

という理解につなげる。

また、

```text
2周波
≠
RTK
```

であることを再確認する。

2周波に対応しているスマートフォンやGNSSウォッチでも、

> 外部のRTK補正情報を利用している

という意味にはならない。

### GPS以外の衛星系について

L1 / L2 / L5はGPSを中心にした周波数名である。

iPhoneやGarmin等のマルチGNSS機器では、GPSだけでなく、

- QZSS
- Galileo
- その他の対応GNSS

も利用するため、各衛星系ではE1 / E5a等の対応する周波数帯を利用する場合がある。

そのため教材では、

> 「L1 + L5対応」と「GPSだけを使っている」は同じ意味ではない

ことにも注意する。

### iPhone 15 Proの表現について

Apple公式仕様では、iPhone 15 Proについて「高精度2周波GPS（Precision dual-frequency GPS）」とされている一方、iPhone 15 Proの仕様ページではL1 / L5という周波数名自体は明記されていない。

そのため正式な教材実装では、

```text
iPhone 15 Pro
→ 高精度2周波GNSS
```

を基本表現とし、

```text
L1 + L5
```

まで明示する場合は、実装時点のApple公式資料等で再確認する。

Garmin Forerunner 265については、Garmin公式資料でL1 / L5の2周波受信が明記されている。

この比較は、第2章「なぜ複数周波数を使う？」の具体例、または横断ガイドの補助情報として使用する候補とする。

```text
③ よく混同する言葉
DGNSS方式 vs DGNSS表示
3D fix vs RTK FIX
2周波 vs マルチGNSS
```

中心UIは、

- 早見表
- 短い説明
- 「よくある勘違い」
- 必要に応じた関連章へのリンク

とする。

操作によって理解が明確に深まる内容がない限り、不要なトグルやシミュレーションは設けない。

## 13.6 実装前の確認

Drogger、u-blox等の状態表示や用語は、機種・ファームウェア・アプリの表示仕様によって変わる可能性がある。

正式実装前には、

- BizStation / Drogger公式資料
- u-blox公式Interface Description等
- 対象機器の現行マニュアル

を確認し、表示名と意味を最新状態で検証する。

# 14. 応用編候補「自社機器で携帯圏外RTKをどう構成するか」

## 14.1 位置付け

第6章「自前RTK② 補正情報を届ける」で、

- RTCMはGNSS情報のデータ形式・メッセージ規格
- NtripはRTCM等のGNSSデータをIPネットワーク経由でストリーミングする仕組みで、一般的な運用ではインターネットを利用する
- Ntripを使わず、無線・シリアル等の別経路でRTCMを移動局へ届ける構成もある

ことを学習した後の**実務応用編**として扱う候補とする。

中心となる問い：

> 携帯通信圏外の現場で、自社保有機器を使って自前RTKを成立させるには、基準局から移動局へRTCMをどのような構成で届ければよいか。

第6章本編では一般原理までに留め、この応用編で自社機器に即した具体構成を検討する。

## 14.2 現時点の自社機器

基準局候補：

```text
Drogger Pパッケージ
DG-RPO1RWS + u-blox ANN-MB-00
```

移動局候補：

```text
Drogger RWX
```

これらを前提候補とするが、正式な構成は機器の現行仕様・入出力インターフェース・対応ファームウェアを確認してから確定する。

## 14.3 応用編で比較したい通信構成

少なくとも次を候補として比較する。

```text
A. Ntrip（一般的なインターネット経由）
基準局 → RTCM → Ntrip Server → Internet → Caster → Ntrip Client → 移動局

B. Ntrip（ローカルIPネットワークを使う応用構成）
基準局 → RTCM → Ntrip Server → ローカルIPネットワーク → Caster → Ntrip Client → 移動局

C. Ntripを使わない直接伝送
基準局 → RTCM → 無線・シリアル等 → 移動局
```

必要に応じて、次の伝送方法を調査する。

- 外付け無線モデム
- シリアル入出力
- Bluetooth等によるローカル伝送
- ローカルWi-Fiでの伝送可否
- その他、対象Drogger機器が公式に対応するRTCM入出力方法

「直接RTCM」は正式な通信規格名としてではなく、Ntrip/Casterを介さず別の通信経路でRTCMを直接届ける構成を説明する教材上の表現として扱う。

## 14.4 応用編で確認する実務条件

単に接続できるかではなく、少なくとも次を確認する。

- 基準局側で出力できるRTCMメッセージ
- 移動局側で受信できるRTCM入力方法
- 必要な追加機器・ケーブル・インターフェース
- 通信可能距離
- 見通し・地形・森林・谷地形による通信影響
- RTCMの遅延・欠落・更新停止の確認方法
- 電源・連続運用時間
- 無線を利用する場合の周波数・出力・法令・免許等の条件
- 基準局1台に対して複数移動局を使う場合の構成可否
- 現場で通信が切れた場合の復旧・代替手順

## 14.5 教材上の中心メッセージ

```text
携帯圏外
≠
自前RTKができない
```

重要なのは、

> 基準局側のRTCMを、必要な鮮度で継続して移動局へ届けられる通信経路を用意すること。

Ntripはその方法の一つである。一般的にはインターネット経由で利用するが、Ntrip自体はIPネットワーク上でGNSSデータをストリーミングする仕組みとして扱い、公衆インターネット必須とは断定しない。現場条件によってはローカルIPネットワークや、Ntripを使わない無線・シリアル等の別経路も検討できる。

ただし、無線等を使えば必ずRTKが成立するとは説明しない。GNSS観測環境、機器対応、通信距離、地形、法令、必要精度等を含めて判断する。

## 14.6 正式要件化前の再確認

この応用編を正式要件化するときは、実装時点の最新公式資料を確認し、少なくとも次を再検証する。

- BizStation / Drogger公式資料
- 対象受信機の現行仕様・マニュアル
- RTCMの入出力対応
- シリアル・Bluetooth・Wi-Fi等の対応条件
- 必要な追加ハードウェア
- 無線関連法令・利用条件

推測で自社機器の構成を固定しない。

# 15. 第6章「自前RTK② 補正情報を届ける」正式要件化前の確定事項

## 15.1 第5章・第7章との役割分担

第5章では、基準局座標、アンテナとの結び付け、観測環境を確認し、基準局を成立させるところまでを扱う。

第6章では、成立した基準局側の情報を移動局へ正しく・継続的に届ける仕組みを扱う。

第7章では、移動局へ届いた基準局側の情報と移動局自身のGNSS観測を使い、相対的な位置関係、FLOAT / FIX、基線解析を理解する。

```text
第5章
基準局をつくる
  ↓
第6章
RTCM等を移動局へ届ける
  ↓
第7章
届いた情報を使ってRTK解析・FLOAT → FIX
```

第6章の到達点は、

> 移動局へ必要な基準局側情報が正しく、継続して届いていることを確認できる。

とし、FIXの成立そのものを第6章の到達点にはしない。

## 15.2 第6章の9カード構成

正式要件化時は、原則として次の9カード構成を使用する。

```text
カード1　基準局をつくった。その次は？
カード2　基準局は何を移動局へ送る？
カード3　RTCMとは？
カード4　Ntripとは？
カード5　Casterは何をしている？／Mountpoint
カード6　自前RTKの情報経路を追う
カード7　RTCMの届け方はNtripだけ？
カード8　届いていても「古い」ことがある
カード9　どこで止まっている？
```

カード1で章全体の「地図」を提示し、カード2以降でも同じ地図を再利用して、現在学習している箇所だけを強調する。

基本地図：

```text
GNSS衛星
  ↓
基準局AでGNSS観測
  ↓
RTCM
  ↓
Ntrip Server
  ↓
IPネットワーク
  ↓
Ntrip Caster
  │
  └─ Mountpoint
  ↓
Ntrip Client
  ↓
移動局P1
  ↓
第7章：FLOAT → FIX
```

## 15.3 RTCMの教材上の扱い

中心メッセージ：

> RTCMは、基準局の位置やGNSS観測などを機器間で共通に扱うための標準的なデータ形式・メッセージ規格である。

第6章では、RTCMを「1個の補正値」や「P1の完成座標」として説明しない。

具体例として、次のような代表的なRTCMメッセージを使用してよい。

```text
1005　基準局ARPの位置
1077　GPSの観測情報
1097　Galileoの観測情報
1127　BeiDouの観測情報
```

番号暗記を目的にしない。

RTCMは1回送って終わるファイルではなく、複数種類のメッセージがストリームとして継続的に流れることを図示する。

```text
1005
1077
1097
1127
1077
1097
1127
...
```

移動局では、利用者がRTCM番号を手動で組み合わせるのではなく、受信機が届いたRTCMと自分自身のGNSS観測を整理・組み合わせながら測位解を継続的に更新する、と理解させる。

## 15.4 RTCMとNtripを明確に区別する

```text
RTCM
＝ 届ける情報の中身・形式

Ntrip
＝ GNSSデータをIPネットワーク経由でストリーミングする仕組み
```

初心者向けには、一般的な利用例として「NtripでRTCMをインターネット経由で届ける」と説明してよい。

ただし、正式要件では、

> Ntrip ＝ 公衆インターネット必須

とは断定しない。

NtripはIPネットワーク上で動作する仕組みとして扱い、一般的なインターネット経由の構成と、応用的なローカルIPネットワーク構成を区別する。

## 15.5 CasterとMountpoint

中心メッセージ：

```text
Caster
＝ 複数のGNSSデータストリームを扱う配信所

Mountpoint
＝ Caster内の1本のデータストリームを識別する名前
```

MountpointはRTCMメッセージ1個ごとの名前ではない。

教材例：

```text
Mountpoint：BASE_A
├─ 1005
├─ 1077
├─ 1087
├─ 1097
├─ 1127
└─ ...継続して流れる
```

教材では分かりやすく、

```text
BASE_A → 基準局AのRTCMストリーム
BASE_B → 基準局BのRTCMストリーム
```

と1対1の例を使用してよい。

ただし、Mountpointは基準局そのものの名前ではなくストリーム識別名であり、構成によっては同一基準局から複数ストリームを別Mountpointとして提供できることを小さく補足する。

## 15.6 Ntrip Server / Caster / Clientは役割として理解する

第6章では、Server / Caster / Clientを必ず別々の物理機器として描かない。

```text
Ntrip Server
→ 基準局側のRTCMストリームをCasterへ送る役割

Ntrip Caster
→ ストリームを受け取り、識別し、Clientへ配信する役割

Ntrip Client
→ Casterへ接続し、必要なストリームを受信する役割
```

ServerやClientの機能が受信機やアプリ内に組み込まれる場合があることを示す。

### カード6の通信方向

Mountpointの理解を明確にするため、カード6では単方向の矢印だけにしない。

```text
Ntrip Client
   │
   │ 「BASE_Aを受信したい」
   └────────────→ Ntrip Caster

Ntrip Caster
   │
   │ BASE_AのRTCMストリーム
   └────────────→ Ntrip Client
```

つまり、Client側がMountpointを指定してストリームを要求し、Caster側から対象ストリームが返る関係を示す。

## 15.7 Ntripを使わないRTCM伝送

第6章では、

> RTKに必須なのはNtripそのものではなく、基準局側のRTCMを必要な鮮度で移動局へ届けること。

と理解させる。

比較例：

```text
A. Ntripを使用
基準局 → RTCM → Ntrip Server → IPネットワーク → Caster → Client → 移動局

B. Ntripを使用しない
基準局 → RTCM → 無線・シリアル等 → 移動局
```

Ntripを使わない直接伝送では、Ntrip Server / Caster / Mountpoint / Ntrip Clientは不要になる。

「直接RTCM」は正式な通信規格名ではなく、教材上の説明表現として扱う。

## 15.8 RTCMの鮮度・遅延・停止

カード8では、

```text
正常
遅延
停止
```

の3状態を比較する操作を候補とする。

中心メッセージ：

> 「通信が接続中」と「新しいRTCMが継続して届いている」は別である。

RTCMの最後の更新からの時間、Caster側の最終受信時刻、受信量の増加などを確認材料として扱う。

ただし、表示項目名は機器・Caster・アプリによって異なるため、

- Last Received
- Correction age
- Active
- Clients
- データ量

等を全機器共通の固定名称として扱わない。

また、

```text
5秒なら異常
10秒ならFLOAT
```

のような普遍的なしきい値は教材に設定しない。

Drogger等の具体的な秒数表示を紹介する場合は、必ず「その製品・画面の表示仕様の具体例」と明示する。

## 15.9 カード9のトラブル切り分け

カード9は、第6章の学習内容を現場判断へつなげる操作カードとする。

基本確認順：

```text
基準局でGNSS観測
  ↓
RTCM出力
  ↓
送信経路
  ↓
Caster / Mountpoint（Ntrip使用時）
  ↓
受信経路
  ↓
移動局でRTCM更新
```

候補ケース：

- 基準局からRTCMが出ていない
- Caster接続は成功しているがMountpointが違う
- 接続中だがRTCM更新が停止している
- Ntripを使わない無線経路で受信できていない
- RTCMは正常に届いているがFLOATのまま

最後のケースでは、

> 第6章の通信経路としては正常。次は第7章で、届いた基準局側情報と移動局自身の観測をどう使ってFLOAT / FIXになるかを考える。

とつなげる。

```text
カード2　静的
カード3　静的
カード4　静的
カード5　静的
カード6　静的
カード7　静的
カード8　操作あり：正常 / 遅延 / 停止

```

## 15.11 Drogger公式情報源と教材内リンク方針

Drogger関連の教材内容を検討・実装するときは、次を公式情報源として参照する。

```text
BizStation / Drogger公式マニュアル
https://www.bizstation.jp/ja/drogger/

Drogger公式ブログ
https://drogger.hatenadiary.jp/
```

Drogger公式ブログは、実機の設定、FIX / FLOAT、観測上の注意、Drogger Processor、新機能等について、公式マニュアルを補足する情報源として使用する。

第7章以降の各教材カードでは、カード内容に対応するDrogger公式マニュアルまたはDrogger公式ブログの記事がある場合、カード下部に「Drogger実機で確認」等の補助リンクを付ける。

ただし、次の方針を守る。

- 該当する公式解説があるカードだけにリンクを付ける
- 二重差、整数アンビギュイティ決定アルゴリズム等、Drogger公式資料に直接の解説がない理論内容へ無理にリンクを付けない
- 実機表示・設定と一般的なGNSS理論を混同しない
- Drogger固有の表示名・しきい値・動作は、Droggerの実機例であることを明示する
- 必要に応じて国土地理院、ESA、u-blox等の一次資料も併用する

第7章では、特に次の内容についてDrogger公式情報との接続を確認する。

- RTCM受信状況、Status、RTCM3、Age
- FIX / FLOATの実機表示
- 基準局と移動局の相対測位
- FIX維持、遮蔽、搬送波位相の連続追跡
- ミスFIX（false fix）と観測環境
- 基準局座標、アンテナ高
- 元期・今期、地殻変動補正

教材設計時点で該当ページを確認し、URLが変更されている可能性もあるため、正式実装要件を作成する時点で最新の公式ページを再確認する。
